# アーカイブ対応範囲

## v0.1 の対象

ディレクトリまたは ZIP から，同じ階層にある次のファイルを読みます．
外側のフォルダ名は固定していません．ZIP のファイルは展開しません．

```text
<任意のルート>/data/account.js
<任意のルート>/data/tweets.js
<任意のルート>/data/tweets-part1.js
<任意のルート>/data/tweets-part2.js
```

`tweet.js`，`tweet-partN.js`，同じ名前規則の `.json` も対象です．
JSON の前の `window.YTD.tweets.part0 =` 等は，限定した正規表現で除去します．
JavaScript を実行することはありません．末尾のセミコロンを除いた残りは
厳密な JSON 配列でなければ受け入れません．

```javascript
window.YTD.tweets.part0 = [
  {
    "tweet": {
      "id_str": "1234567890123456789",
      "created_at": "Sat Jun 14 14:18:00 +0000 2025",
      "full_text": "この本文は書式説明用の合成例です。",
      "entities": {}
    }
  }
];
```

account.js は一要素の配列で，`account.accountId` を含む形式です．
数値IDは浮動小数点に変換せず，文字列として保存します．
取込時の本文はレガシーアーカイブの HTML エスケープを一度だけ解除し，
改行 CRLF/CR を LF に揃えます．大文字小文字，前後の空白，Unicode 正規化は変更しません．
この差異により live API の本文と一致しない場合は削除を拒否し，自動的に一致条件を緩めません．

DM，フォロー情報，いいね履歴などのファイルは読みません．
対応する投稿ファイル以外を網羅的に解釈する汎用 X アーカイブライブラリではありません．
ファイル名規則自体が異なる形式は，人間による適合確認とパーサー追加が必要です．

## 停止または保留にするもの

別の `note-tweet.js` / `note_tweet.js` 系ファイルを検出した場合，
長文本文を読まずに「全件取込済み」とすることを避けるため，取込を停止します．
この形式を実データで確認して結合する実装は未実装です．

通常の `full_text` が長い場合は，パーサーで切り捨てません．
分類の文字数ガードに触れればモデル未評価の保留になり，
切れた API の本文を完全な本文とみなして削除することはありません．
ただしアーカイブ中の未知の付加フィールドすべてから欠損を発見できる保証はありません．

同一IDのレコードは，内容と属性が同じなら重複排除します．異なれば取込全体を中止します．
複数のアーカイブルートが混ざる場合や，アカウント情報が複数ある場合も中止します．
サイズは対象ファイル1個256 MiB，対象ファイル合計512 MiBまでです．
一つのJSON配列をメモリへ読み込むため，巨大アーカイブのストリーミング解析は未実装です．
実際のメモリ使用量はJSONのバイト数より増えます．

## 投稿種別

通常の本人投稿は分類・確認・条件付き削除の対象です．
返信・引用・メディア・リンク付き投稿は文脈不足等のフラグを付けます．
それらは自動削除せず，人間の確認候補へ回します．
画像・動画・リンク先・返信先の内容を取得する機能はありません．

再投稿は削除処理の対象外です．`RT @` で始まる投稿も安全側に同じ扱いにします．
この規則では，手入力した「RT @」で始まる本人投稿も除外され得ます．
再投稿取消し API の実装は含みません．編集履歴がある投稿も初版では削除しません．
X Articles の専用取込・削除も未実装です．

アーカイブ取得後に追加された投稿を API で同期する機能はありません．
再度アーカイブを取得して ingest する方法になります．
アーカイブから消えていた行を再取込時に DB から削除する同期処理も行いません．
実削除の直前には現在の X と照合するため，既に消えた投稿は削除成功と誤認しませんが，
未検証の古い行が確認候補に含まれる可能性は残ります．
